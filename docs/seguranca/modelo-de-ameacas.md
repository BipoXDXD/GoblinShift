# Modelo de ameaças por fluxo (STRIDE)

Referência: `main` em `cc1dd2cc`. Cada linha liga ameaça → mitigação (`arquivo:linha`) → teste
(`arquivo::teste`). **SEM TESTE** marca mitigação sem teste automatizado no repositório; **lacuna**
marca ameaça sem mitigação no código. `tests/security/test_threat_model.py` confere que todo
arquivo e teste citado existe e que toda linha citada existe no arquivo.

Letras: S spoofing, T tampering, R repudiation, I information disclosure, D denial of service,
E elevation of privilege.

## Fora do escopo deste documento

Borda e infraestrutura não são modeladas aqui: Cloudflare, Nginx (TLS, HSTS, limite de `/auth`),
gateway e confiança no IP do cliente (ADR 014, 041, 043), firewall, `compose*.yaml`, papéis do
banco, DoS de camadas 3 e 4. Os testes que já existem para elas (`tests/test_nginx_*.py`,
`tests/test_gateway_client_ip.py`, `tests/test_compose_*.py`) não são revisados aqui.
